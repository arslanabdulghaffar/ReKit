`609190e623c2561b067b871383fabfba1b1b2606`.

Its silent draft uses recorded stills, not motion footage. The original
[recording workflow](demo-recording-workflow.md) and historical

The central story is accountable recovery: preserve uncertain evidence, correct
an assertion without erasing it, compare complete allocations, then reserve and
record completion against unique physical IDs. Separate the original-product
inspection from the invented recovery case throughout. The former does not
supply inventory or verified parts to the latter.

The canonical replay creates the high-labor proposal before the baseline and
competing proposals. The edit explains the baseline first for comparison, using
two explicitly saved-proposal stills. It must not imply that the operator changed
an already approved plan in place or executed liquidation before rebuilding.
The API receipt keeps even scenario metadata identical in its sensitivity check;
the browser's generated scenario IDs and descriptions differ while its economic
inputs, catalog, policy and evidence remain equal except for labor rate.

The baseline calculation is `2 × ($100 − 30 × $0.25 − $5) = $175`.
Liquidation is `$105 − 10 × $0.25 = $102.50`; retention is `$6 + $6 + $2 + $2 = $16`
in noncash donor value. At $2/minute those first two values become $70 and $85.
Demand is two kits and total labor capacity is 60 minutes. Retention is an
alternative, not a second deduction. Show these assumptions in the description
or supporting slide so the viewer can verify the comparison.

## Exact manual motion and narration actions

1. Owner chooses a private recording folder under ignored `var/`, with local
   access restricted to the owner. Keep original captures and the editing
   project. Close unrelated windows and disable notification previews.
2. Open the installed OBS manually. Create a dedicated ReKit scene and choose
   application **Window Capture** for the ReKit browser, not desktop-wide
   capture. Disable desktop audio; select only the intended microphone if
   recording voice. Confirm the preview contains no other window. Use the
   recorder's local recording control, never streaming. A brief nonsensitive
   sample must prove framing and intelligible audio before the full take.
3. Preserve all existing OBS profiles/settings. Do not install plugins or change
   the CUDA environment. If a compatible capture source or microphone cannot be
   selected, stop at the prepared still draft and resolve that setup manually.
4. In a private terminal at the repository root, run the two read-only preflights:

   ```powershell
   .\.venv\Scripts\python.exe evaluation/run_demo.py --mode canonical-recovery --check
   .\.venv\Scripts\python.exe evaluation/run_demo.py --mode product-ai --check --device 1
   ```

5. For new canonical motion, run the following once. Start OBS recording **only
   after automatic sign-in finishes and the application workbench is visible**.
   Do not record the terminal, sign-in fields or temporary credential manifest.
   Automation may advance beyond intake before recording begins; use the dated
   intake still for that opening instead of exposing login. The first sample
   determines whether the manual start is practical.

   ```powershell
   .\.venv\Scripts\python.exe evaluation/run_demo.py --mode canonical-recovery --headed --slow-mo-ms 300 --hold-seconds 120
   ```

6. Let automation finish without interacting. It exercises: intake and original
   views; B assertion and policy denial; new A close-up and held state; A
   correction; high-labor proposal; baseline and competing proposals; baseline
   approval; failed competing approval; two completions; inventory-to-source
   navigation; mobile checks. The final 120-second hold permits inspection after
   acceptance assertions. Any manual navigation during that hold is additional
   footage, outside the acceptance checks. Stop OBS before the hold expires and
   let the launcher remove its own temporary state and credentials.
7. Keep the existing NVIDIA stills for the immediate edit. If the owner chooses
   fresh NVIDIA motion, start one separate replay only after canonical cleanup:

   ```powershell
   .\.venv\Scripts\python.exe evaluation/run_demo.py --mode product-ai --headed --slow-mo-ms 300 --hold-seconds 120 --device 1
   ```

   This command makes one real **local NVIDIA** request. Capture after sign-in,
   retain actual output and use its own receipt for any timings. Do not retry
   merely to get more favorable text. A visible “Inference wait shortened” label
   is required for compressed motion footage. Existing stills require no request
   and make no elapsed-motion claim. This command never authorizes AMD inference.
8. Check each new run's `runner-result.json`, `acceptance-result.json` and, for
   product mode, `product-inference-results.json`. Require successful mode checks,
   empty page/cleanup errors and removal of owned temporary state/credentials.
   Record its exact source commit and hashes. Do not mix new imagery with old
   timings or quietly substitute a failed result.
9. Read the narration aloud once, record it locally, and measure the actual
   duration. The timestamps above are editorial allocations, not measured speech.
   Trim pauses or wording while preserving source and limitation statements.
   Keep the AMD closing section on a separate audio/edit track.
10. In the owner's chosen local editor, place footage/stills on a 1920 × 1080
    canvas without stretching. Keep provider/synthetic captions visible. Use
    simple cuts, with a clear transition at 1:00. Label every still as a still;
    disclose detail crops. Retain full-context source frames privately. Add
    credits below, export a fresh file, and inspect the entire picture and audio.
    Confirm the actual form's duration, size and format requirements before release.
